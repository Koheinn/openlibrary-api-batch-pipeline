# Open Library API Batch Data Pipeline

A Python-based batch data pipeline built as part of **Course 2 of the DeepLearning.AI Data Engineering Professional Certificate** on Coursera.

The project demonstrates how to interact with a public REST API, retrieve data in batches, handle pagination, extract related entities, and save processed data as JSON.

The pipeline uses the **Open Library API** to retrieve programming-related works published between **2022 and 2026**, extract their authors, retrieve additional author information and works, and store the resulting dataset locally.

---

## Project Overview

This project focuses on the fundamentals of **API-based data ingestion** and **batch processing**.

The pipeline follows these main steps:

1. Request programming-related works from the Open Library Subjects API.
2. Handle API pagination to retrieve all available works.
3. Extract author keys from the returned works.
4. Remove duplicate author keys.
5. Request detailed information for each unique author.
6. Retrieve each author's works using pagination.
7. Combine author details and works into a structured dictionary.
8. Save the processed data as a timestamped JSON file.

The overall workflow can be summarized as:

```text
Open Library API
       │
       ▼
Programming Works
(2022–2026)
       │
       ▼
Pagination
       │
       ▼
Extract Author Keys
       │
       ▼
Remove Duplicates
       │
       ▼
Author Details + Works
       │
       ▼
JSON Output
```

## Open Library API

This project uses the public [Open Library](https://openlibrary.org/) API.

No API key or authentication is required for the API calls used in this project.

The main API endpoints used are:

### Subjects API

Used to retrieve works associated with a subject.

```text
GET /subjects/<subject>.json
```

The project uses:

```text
https://openlibrary.org/subjects/programming.json?published_in=2022-2026
```

The `published_in` parameter filters the results by publication year.

### Author Details API

Used to retrieve information about an individual author.

```text
GET /authors/<author_id>.json
```

### Author Works API

Used to retrieve works written by an author.

```text
GET /authors/<author_id>/works.json
```

## Pagination

Pagination is an important part of this project.

APIs commonly return only a limited number of records per request. Instead of requesting everything at once, the pipeline repeatedly requests different pages using `offset` and `limit`.

For example:

```text
offset=0&limit=50
offset=50&limit=50
offset=100&limit=50
...
```

The pipeline continues requesting data until there are no more works available.

This approach allows the application to process API datasets that are larger than a single API response.

## Batch Processing Workflow

The batch pipeline implemented in `main.py` follows this process:

### 1. Retrieve works

```python
works = get_paginated_works_by_subject(
    base_url=URL_SUBJECT,
    **kwargs
)
```

The configured subject endpoint targets programming-related works published between 2022 and 2026.

### 2. Extract authors

Each work can contain multiple authors.

The pipeline extracts their author keys:

```python
for work in works:
    authors = work.get("authors", [])

    for author in authors:
        key = author.get("key")

        if key:
            author_keys.append(key)
```

### 3. Remove duplicate authors

The same author can appear on multiple works, so duplicate author keys are removed:

```python
author_keys = list(set(author_keys))
```

### 4. Retrieve author data

The pipeline then retrieves details and works for every unique author:

```python
for author_key in author_keys:
    author_data = get_authors(
        base_url=BASE_URL,
        author_key=author_key,
        **kwargs
    )

    author_items[author_key] = author_data
```

### 5. Save the results

The final data is saved as a timestamped JSON file:

```text
author_items_<timestamp>.json
```

## API Rate Limiting

When working with public APIs, it is important to respect the API provider's rate limits.

The Open Library API uses soft rate limiting. Making requests too quickly can result in delays or temporary blocking.

For production-quality pipelines, additional techniques could be considered, such as:

* Request throttling
* Retry logic
* Exponential backoff
* HTTP status-code handling
* Logging
* Caching
* Configurable request intervals
